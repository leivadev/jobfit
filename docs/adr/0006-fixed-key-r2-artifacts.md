# Fixed-key R2 artifacts, not versioned keys

Each Offline Pipeline run uploads `jobs.index` and `jobs_metadata.parquet` to the same fixed R2 keys, overwriting the previous run in place. We considered timestamped/hash-suffixed keys with a separate pointer the backend reads to find the current version, which would allow rollback and safe A/B comparisons. We rejected it for the MVP: there's no rollback or A/B requirement in scope, and a pointer/manifest scheme is real complexity (plus a new failure mode — the pointer itself can point at a partially-uploaded pair) for a benefit nobody's asked for yet. This means `Artifact` (see `CONTEXT.md`) is not versioned in any retrievable sense — only the current run's output exists in R2. It also means a run that uploads one file but fails on the other can leave the backend loading a mismatched Job Index / Job Metadata pair at next startup; accepted as a known gap, not solved here. Revisit if rollback, A/B, or zero-downtime reindexing becomes a real requirement.
